# StrixOps v1.1.0

Release date: 2026-09-10.

Setup and usage: [English README](../README.md) · [简体中文](../README.zh-CN.md) ·
[MCP operation guide](mcp-traffic-workbench.md).

This release adds an independent MCP traffic workbench. Existing Web/internal
tasks retain their runner, storage, and container lifecycle.

## Included changes

- Create MCP tasks from the sidebar, define allowed/excluded websites, and
  capture HTTP/HTTPS browser traffic in a task-owned proxy container. Inspect
  observed pages and APIs, replay requests, and retain their evidence.
- Test selected requests with saved Web model routes and compatible
  prompt/skill snapshots. Request execution uses separate short-lived containers
  and bounded budgets. Save results and generate versioned Markdown reports.
  The same task operations are available through Streamable HTTP MCP tools.
- Reuse one persistent CA across all tasks in the same MCP data directory.
  Import the public CA once per test browser/profile; capture restarts and task
  deletion do not rotate it. Publish only the public certificate and SHA-256
  fingerprint, keeping the private key in the persistent data directory.
- Prevent long task names, URLs, headers, and report content from stretching
  frontend columns; full values remain available in detail views.
- Delete a task from the list or detail view after confirmation. Deletion stops
  its proxy, cancels and waits for active jobs, and removes its saved traffic,
  results, reports, and session files. It preserves the shared CA and other
  tasks; failed cleanup retains a task record for retry.

## Upgrade from source

The release is tagged `v1.1.0`. For a fresh checkout, follow the README. To select
the exact release in an existing checkout, preserve any local changes first:

```bash
git fetch origin tag v1.1.0
git switch --detach refs/tags/v1.1.0
npm --prefix console/web ci
npm --prefix console/web run build
uv sync --frozen --no-dev
docker pull ghcr.io/mitmproxy/mitmproxy:12.2.3@sha256:00b77b5d8804c8ad18cb6caefbf9d5849e895e8986c5ce011f4ae30f4385962f
```

Restart the Console using the same configuration and persistent data paths to
load the rebuilt frontend and updated backend. Use a single Console worker for
each MCP data directory. New Python dependencies include `mcp==1.29.1` and
`cryptography>=42`; install from `uv.lock` rather than updating individual
packages. MCP capture requires the pinned image above to be installed; starting
a proxy does not pull it automatically.

MCP data defaults to `~/.strixops/mcp_tasks`, separate from the existing runs
directory, and can be relocated with `STRIXOPS_MCP_ROOT`. Keep this directory
persistent, including its `ca/` directory. During migration, the service prefers
an existing valid CA. A browser that already trusts the adopted CA needs no
new import; a browser trusting a different legacy CA must trust the shared one.
Each browser/profile has its own trust configuration.

The upgrade does not automatically restart existing proxies. A running legacy
proxy keeps its original certificate until its next start; the UI indicates
when it differs from the shared CA. To switch that proxy, stop and restart its
capture session, then update the browser's proxy address if the port changes.
Changing the data directory, replacing the CA, or certificate expiry requires
updating browser trust.

The assessment sandbox remains `strixops-sandbox:1.3.0`. The MCP image is
separate, and neither image is bundled in the Python wheel. The README's wheel
installation examples describe a locally built or otherwise available trusted
artifact; they do not imply a binary upload or PyPI publication. There is no
release CI workflow in this repository.

## Scope and verification

MCP records network requests that pass through the configured browser proxy.
It does not promise a complete site inventory, DOM navigation recording,
pause-and-edit interception, or arbitrary Agent exploration. Tests work on
selected requests with the capabilities and limits documented in the
[operation guide](mcp-traffic-workbench.md).

Local verification covered regression tests, real Docker HTTP/HTTPS capture,
shared trust across tasks and restarts, deletion and container isolation, and
Chromium checks for long content and task deletion. Development test suites and
fixtures remain outside the published repository and distribution packages.
