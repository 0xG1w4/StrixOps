# StrixOps v1.2.2

Release date: 2026-09-12.

Evidence lists now show only attachments that were saved and remain available
for download. Counts and categories use the same available-file list. Missing,
failed or unavailable attachments remain excluded from downloads and ZIP evidence
entries, while their diagnostic records stay in the private manifest.

Evidence collection is best effort. Missing path references in findings no longer
fail an otherwise successful Web or Internal task. Collection and copy errors
remain in run metadata for diagnosis, and deterministic and model-synthesized
reports use the saved attachment inventory. A completed task does not guarantee
that every mentioned file was created or that assessment coverage is complete.

Agent and runtime failures, container cleanup errors, and failures to persist
required run state or reports still fail the task.

## Upgrade

Let active tasks finish before upgrading and keep existing persistent paths.

```bash
git fetch origin tag v1.2.2
git switch --detach refs/tags/v1.2.2
npm --prefix console/web ci
npm --prefix console/web run build
uv sync --frozen --no-dev
```

Restart Console after upgrading. New tasks use the revised evidence policy.
Existing failed task records are not automatically rewritten. The upgraded
Console also filters unavailable attachments from older tasks' evidence lists.
No task-data migration, sandbox image rebuild or certificate reimport is required.
