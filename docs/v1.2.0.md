# StrixOps v1.2.0

Release date: 2026-09-12.

This release adds saved FOFA searches and queued target batches. A new
multi-target submission creates independent target assessments, with separate
containers, Agent context, notes, evidence and reports. Batch membership does
not imply that its targets are related.

## FOFA

Open Settings to save the FOFA Email/API Key, then use FOFA in the sidebar.
Searches save fetched results and distinguish completed, partial and failed
acquisitions. Filtering, sorting, pagination and reopening history use saved
data. CSV and JSON exports apply to the current filters.

Select HTTP(S) assets and create a draft in the existing task form. Review the
targets, project scope, model, instructions and concurrency before submission.
Original targets retain search/result provenance; edited or added targets are
not attributed to a different FOFA result. Unsupported service protocols remain
viewable and exportable but require explicit target-type review.

Credentials stay in private server-side configuration, separate from exported
assets and task artifacts. FOFA search does not start an Agent or container.

## Independent batches

All new multi-target Console/API and CLI submissions use the batch scheduler.
Each batch defaults to two concurrent targets. Settings provides a separate
host-wide limit, also defaulting to two, shared by ordinary Console and CLI
assessments using the same queue store. Single-target tasks wait for this
capacity before starting their sandbox. MCP capture/request-test containers
retain their separate lifecycle and are outside this limit.

The batch page lists each target's queue state and independent task/report.
Cancel a target or the remaining batch; deleting a terminal batch removes its
grouping and private launch snapshot while preserving completed run files.
Existing historical multi-target shared reports are retained as originally
generated. Optional project reports remain explicit aggregations.

CLI multi-target commands accept `--max-concurrent 1..16` and `--batch-name`.
Use `--resume-batch ID` to resume supervision of a saved CLI batch. This does
not restore an interrupted Agent conversation or rerun completed targets.

See the [FOFA and target batch guide](fofa-and-target-batches.md) for storage,
resource limits and recovery details.

## Upgrade

```bash
git fetch origin tag v1.2.0
git switch --detach refs/tags/v1.2.0
npm --prefix console/web ci
npm --prefix console/web run build
uv sync --frozen --no-dev
```

Let existing assessments finish before upgrading and restarting Console: an
older running engine cannot participate in the new capacity accounting. Keep
the same persistent settings and runs paths. New FOFA and queue stores are
created automatically; no existing run migration, sandbox image rebuild or
certificate reimport is required.
