# StrixOps v1.3.0

Release date: 2026-09-13.

Adds one Console account (`strix`), a login screen, first-login password change,
server-side sessions, a Strix avatar account menu and the five latest successful
logins. All Console APIs and downloads require login; mutations require CSRF.
Existing scans, MCP containers, proxy certificates, prompts, skills and data remain
independent of browser sessions. Logout does not stop work.

## Upgrade

Complete outstanding work, update your checkout and run:

```bash
./strixops.sh install
./strixops.sh start
./strixops.sh status
```

Reload the browser. The initial login is `strix / strix123`; change this password
before accessing the workspace. Subsequent upgrades preserve the changed password.
Set up HTTPS before using the initial login on an untrusted network.

Cookie-free REST clients now need to log in and send CSRF for changes. Explicit
MCP tokens work only on `/api/mcp/transport`; old automatic browser tokens do not
bypass login. The public health response no longer exposes paths or task counts.
The manager supports this response and now displays the listening address
separately from the local browser URL.

Next.js remains on the existing patched 15.5 line. Its PostCSS dependency is pinned
to 8.5.26 to resolve the audited advisory. No Docker image rebuild or CA reimport is
required. See [authentication and deployment](authentication.md).
