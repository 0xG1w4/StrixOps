# StrixOps v1.2.4

Release date: 2026-09-12.

Updating source and building the frontend does not replace a running Console
process. An older backend can serve the new page while still lacking its batch
and queue APIs. This caused a generic batch launch error and a disabled host
concurrency field in the reported installation.

The Console now identifies page/backend version mismatches and displays the
running backend version. Batch and queue errors retain their HTTP status and
show actionable messages without displaying raw response bodies. Queue settings
have explicit loading and retry states, preserve unsaved edits during refreshes
and use the saved value returned by the API. Batch submission checks queue
availability and can retry without discarding the target list.

Web targets may include paths such as `/login` and query strings. Target
normalization, independent task reports, host/batch concurrency limits and
scanner execution are unchanged.

## Upgrade

Let active tasks finish before upgrading and retain existing persistent paths.

```bash
git fetch origin tag v1.2.4
git switch --detach refs/tags/v1.2.4
npm --prefix console/web ci
npm --prefix console/web run build
uv sync --frozen --no-dev
```

Restart the Console process using its existing service or launch command, then
reload the browser. For a terminal-launched Console, stop the old process with
Ctrl+C and run the same command again. For a managed deployment, restart its
existing Console service.

Verify that `/api/health` reports `1.2.4` and Settings → Task queue loads the
current host capacity. No data deletion, migration, sandbox image rebuild or
certificate reimport is required.
