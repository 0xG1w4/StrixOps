# StrixOps v1.1.1

Release date: 2026-09-10.

This patch completes the remote browser workflow introduced with the
[MCP traffic workbench in 1.1.0](v1.1.0.md).

## Remote Console access

Set `STRIXOPS_MCP_TOKEN` on the Console server, restart it, then open
`http://<server-ip>:8300/mcp` and enter that token. The browser verifies the
token before loading task data and stores it only in this tab's session storage.
All MCP operations and CA downloads use the same authenticated request path.
Clearing access or a rejected token clears the workbench's browser state.
Existing local access and Web/internal workflows are unchanged.

## Remote browser proxy

The capture listener still defaults to `127.0.0.1`. To connect from a different
computer, explicitly set `STRIXOPS_MCP_PROXY_BIND_HOST` to the server interface
IP and `STRIXOPS_MCP_PROXY_AUTH` to `username:password` before starting Console.
Non-loopback listeners require proxy authentication. For wildcard bindings or
NAT, set `STRIXOPS_MCP_PROXY_PUBLIC_HOST` to the concrete browser-facing address.
The UI displays that address and indicates when the browser needs proxy
credentials; the proxy password is separate from the MCP control token.

These settings apply to new capture sessions. Existing proxies are not restarted
automatically. The shared CA and saved task data remain unchanged. See the
[operation guide](mcp-traffic-workbench.md#直接連接主機-ip) for complete examples,
firewall considerations, and authenticated reverse-proxy deployment.

## Upgrade

```bash
git fetch origin tag v1.1.1
git switch --detach refs/tags/v1.1.1
npm --prefix console/web ci
npm --prefix console/web run build
uv sync --frozen --no-dev
```

Restart Console with its existing persistent paths and the remote settings
above. The mitmproxy image digest and assessment sandbox version have not changed.
This version does not introduce a login system for the other Console pages.
