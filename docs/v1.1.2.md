# StrixOps v1.1.2

Release date: 2026-09-10.

Opening MCP through the Console IP now initializes browser access automatically.
No MCP environment variables or manually generated tokens are required for the
normal IP-based workflow. The server saves one private control token for the MCP
data directory and reuses it after browser or Console restarts.

Starting capture from a remote Console address selects the proxy address and
generates separate credentials for that capture session. Reveal and copy them
from the connection panel when the browser requests proxy authentication.
Passwords remain out of task polling, reports, and connection URLs. A new capture
session receives new proxy credentials; its CA remains the same shared CA.

Automatic setup inherits the existing Console deployment access boundary:
anyone permitted to open that Console can initialize MCP and access its shared
tasks. It does not add user accounts or a separate identity check. Bootstrap
requires a matching browser origin and an IP/localhost address or explicitly
trusted Console domain. Cross-origin bootstrap is rejected. An explicit
`STRIXOPS_MCP_TOKEN` keeps the manual login workflow and cannot be bypassed by
automatic setup; other proxy environment settings remain advanced overrides.

## Upgrade

```bash
git fetch origin tag v1.1.2
git switch --detach refs/tags/v1.1.2
npm --prefix console/web ci
npm --prefix console/web run build
uv sync --frozen --no-dev
```

Restart Console with its existing persistent paths. Open its IP address and
select MCP. Existing captures are preserved; stop and start a capture to apply
the new automatic proxy settings. Explicit v1.1.1 environment overrides continue
to take priority; remove those overrides if you want automatic selection.
The pinned capture image, shared CA, and Web/internal workflows are unchanged.
