# StrixOps v1.1.3

Release date: 2026-09-10.

This patch fixes evidence reference matching, readable MCP response bodies, and
request-test budget management.

## Evidence references

References such as `output/RECON_AUTH_SWEEP_SUMMARY.md` and
`./output/header_idor_results.jsonl` now resolve against the attachment index.
An exact indexed path takes precedence, including a real nested `output/`
directory. Truly missing or undelivered attachments still produce incomplete
evidence; successful delivery is not inferred from a filename alone.

This affects future evidence collection. Existing run files and previously
recorded failure statuses are not rewritten during upgrade.

## MCP body inspection

Captured gzip, deflate, and Brotli bodies are decoded for display and Agent
inspection, including declared text charsets. A gzip JSON response is shown as
JSON rather than binary. Original transfer bytes and headers remain unchanged,
and complete historical captures can use the new preview without recapture.
Textual replay edits remove inherited compression and use a matching UTF-8
charset; unmodified replay preserves the original encoded bytes.

Decompression and previews are bounded. Incomplete data, unsupported encoding,
invalid compressed content, and real binary data have distinct indicators.
Install the updated Python lockfile as well as rebuilding the frontend; Brotli
1.2 or later is required for bounded Brotli previews.

## Request-test timing

New tasks default to 300 seconds and up to 12 replays. Existing task settings
remain in effect, including a saved 120-second limit. The test form explains
that all selected requests share the total budget, which includes model calls,
tools, replays, and finalization. The maximum remains 900 seconds.

Agents receive remaining time and reserve 30% of the budget, capped at 60
seconds, for wrap-up. New replays stop during wrap-up. Partial completion keeps
unassessed checks as `needs_follow_up`, and a hard deadline retains saved
evidence while reporting the phase and elapsed time. Model and tool timing
events help distinguish provider waiting from request execution. Newly generated
reports identify partial completion, exhausted budgets, and available timing.
This does not
guarantee completion with every local model or target within a chosen budget.

## Upgrade

```bash
git fetch origin tag v1.1.3
git switch --detach refs/tags/v1.1.3
npm --prefix console/web ci
npm --prefix console/web run build
uv sync --frozen --no-dev
```

Restart Console using its existing persistent paths. Open an existing MCP flow
to use the new body preview; adjust the budget for the next test in the Agent
test form if needed. Automatic MCP access, proxy credentials, the shared CA, and the
pinned capture image continue to work with the existing configuration.
