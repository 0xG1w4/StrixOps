# StrixOps v1.1.4

Release date: 2026-09-11.

This patch reduces preparation work in MCP request tests and makes model progress
observable. MCP tasks remain separate from Web and Internal scans.

## Earlier access to request evidence

New tests provide bounded, redacted request/response evidence and the compatible
skill catalog in the initial assignment. The Agent can choose a justified replay
without first listing requests, inspecting a small complete sample, and looking
up skill names in separate model rounds. Omitted or shortened evidence is marked;
requests that need more detail still use `inspect_request`.

The default prompt now contains one HTTP-mode contract and compact evidence and
severity guidance. The complete counterevidence and severity skills remain in the
immutable snapshot and can be loaded when needed. Explicitly selected skills are
still injected in full. Loaded skills are identified, and repeated loads do not
append the same content again.

With the bundled defaults and no extra skills, the static system prompt falls
from 21,980 to 5,141 characters. These are character counts, not model token counts
or a claim about inference speed. Tool definitions, selected evidence, operator
instructions and conversation history add to the actual model request.

## Streaming and diagnostics

MCP now uses the SDK streaming runner. Each round reports first-stream-event and
first-model-output timing, tool activity, available token usage, and known finish
or truncation reasons. Diagnostic events contain timing and metadata, not raw
model reasoning, text, tool arguments or provider exception bodies. Reports
include the available measurements; missing provider metrics remain unknown.

The first stream event may only indicate that the connection is active. The first
model output may be reasoning, text or tool-argument activity; neither timestamp
alone measures time to a completed test or successful replay.

The extra MCP-only 2,500-token output cap is removed. The existing model profile's
API mode and reasoning setting remain authoritative, as with Web scans; a default
reasoning setting leaves the decision to the model service. No thinking setting
is silently disabled. The selected endpoint must support the configured streaming
API. Local GLM throughput and gateway behavior still need verification on the
deployment where the model is running.

## Limits and compatibility

- The total time limit still covers model calls, tools, replays and wrap-up.
  New task defaults remain 300 seconds and 12 replays; saved 120-second settings
  remain unchanged. All selected requests share those limits.
- Wrap-up reserves 30% of the budget, capped at 60 seconds. Cancellation stops
  streaming work and joins cleanup; partial evidence and results are retained.
- Scope checks, replay isolation and raw flow evidence are preserved. Each replay
  still uses a short-lived container; this release targets the model preparation
  path rather than changing the replay executor.
- Historical jobs, reports and prompt snapshots are not rewritten. Older test
  records without new metrics remain readable.

## Upgrade

```bash
git fetch origin tag v1.1.4
git switch --detach refs/tags/v1.1.4
npm --prefix console/web ci
npm --prefix console/web run build
uv sync --frozen --no-dev
```

Restart Console with its existing persistent paths. Start a new Agent test to use
the new prompt and streaming flow. No CA reimport or MCP data migration is needed.
